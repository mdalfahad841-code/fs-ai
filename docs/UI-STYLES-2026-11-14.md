# FS AI — UI Styles Mapping (2026-11-14)

All 10 design styles from the Strategy Fox reel ("STOP USING AI DESIGNS AND
USE THESE INSTEAD"), applied to the FS AI website and the owner Command
Center ("Dashboard soho"). One new stylesheet carries everything:
`frontend/styles/ui-styles.css`, loaded last on every page. No other CSS
file was edited, no JavaScript changed, no backend / database / API
behaviour touched. Shared palette (`--blue` / `--navy` / `--amber`) and
type come from `main.css`, so the site still reads as one brand — the
styles complement, they do not clash.

## Public site mapping

| # | Style | Where | Why it fits there |
|---|-------|-------|-------------------|
| 1 | Bento grid | Home `#divisionGrid`, `#articleGrid`, `#toolGridHome`; division page `#divisionArticles` (first tile spans 2 columns, desktop only) | Tiles of different sizes on one neat board — the natural shape for 8 divisions / 25 articles / 20 tools |
| 2 | Glassmorphism | Sticky `.site-header`, `.hero-ring`, `.search-box input` | Frosted panels floating over colour; the header stays readable while content scrolls under it |
| 3 | Neumorphism | `.tool-chip` (raised; pressed when active), `.field` inputs/selects, `.tool-result` | Soft shapes pressed into the surface — controls that invite touch, on the tools page where every control is used |
| 4 | Claymorphism | `.tool-card` (home tool grid) | Puffy, rounded, almost touchable — tool cards are the site's most tappable objects |
| 5 | Neo-brutalism | `.card-tag`, `.status-pill`, `.note-box` (honest numbers) | Thick borders, flat colour, nothing polite — tags and pills must shout their state; the honest-numbers box earns the loud treatment |
| 6 | Minimalism | `.article-body` reading pages (no card chrome, generous leading, hairline rules) | White space does the talking where people actually read |
| 7 | Retro Y2K | `.brand-mark`, `.hero h1 span`, `.hero-ring strong` — chrome gradient, accent only | Chrome and gradients as a restrained 2003 accent; never a whole page |
| 8 | Liquid glass | `.hero` (slow drifting refraction blobs), `.newsletter` panel | Depth and refraction, like water — the two places the site already has colour to refract |
| 9 | Flat design | `.div-icon` chips, table `th`, `.kpi-label`, footer | No shadows, no textures — icons and labels stay plain so the loud styles around them read clearly |
| 10 | Skeuomorphism | `.theme-toggle`, `.nav-toggle` (chunky physical switches with a pressed state) | Buttons that look like real buttons — the two controls the visitor actually presses |

## Command Center (owner dashboard) mapping

The dashboard shares the header, so it inherits glassmorphism (header),
Retro Y2K (brand mark) and skeuomorphism (theme toggle) automatically.
On top of that, per section:

| Style | Where in the dashboard | Why |
|-------|------------------------|-----|
| Bento grid | `.kpi-grid` — Overview, Analytics, Monetization, Autonomy KPI tiles (first tile spans 2 columns, desktop only) | KPI tiles are the dashboard's board; the lead number deserves the big tile |
| Glassmorphism | `#loginCard` (owner sign-in gate) | Frosted panel — the gate looks like a lock screen, not a form |
| Neumorphism | `.field` inputs/selects in every dashboard form (article, division, subscriber filter, autonomy settings) | Same pressed-in controls as the public tools; one control language everywhere |
| Claymorphism | `.kpi-card` (all KPI tiles, incl. Autonomy) | Puffy tiles make the numbers feel touchable without changing their values |
| Neo-brutalism | `.status-pill` (every agent/account/article status), Emergency Stop state | Statuses must be unmistakable at a glance |
| Minimalism | `.table-scroll table` and `.dashboard-section ul.clean` (logs, agent lists, revisions) | Tables and logs are read, not admired — flat rows, hairline rules, air |
| Liquid glass | `#section-autonomy` (Autonomous Operations) | The flagship section gets the depth treatment; it is the one panel that should feel alive |
| Flat design | Table `th`, `.kpi-label` | Labels and headers stay plain under the louder tiles |
| Skeuomorphism | `#emergencyStopBtn`, `#autonomyStopBtn` (red alarm-style physical buttons), `#demoLoginForm .btn-primary` (sign-in key) | The stop buttons must feel like real alarm buttons you press, not links |

## What was deliberately left out

- **owner-setup.html** — no site stylesheets at all. It is a standalone,
  phone-only password-hash utility with inline styles and no site chrome;
  linking the design system there would couple a security tool to the theme.
- **No new font, no CDN, no new dependency** — everything is pure CSS on
  the existing stack; zero cost, nothing to load.
- **No style forced per page** — styles follow the element's job, not the
  page it sits on (e.g. a tag is brutalist on the home page, the article
  page and the dashboard alike).
- **No print changes** — the site has no print stylesheet; nothing here
  alters printing.
- **Retro Y2K kept restrained** — chrome gradient on the brand mark and
  hero headline only; in the light theme the hero headline falls back to
  plain blue so it stays readable.
- **No JavaScript, backend, database or API changes** — the rollout is
  CSS + one `<link>` per page. All 25 articles, 20 tools, 14 dashboard
  sections, the login gate, agent controls, Emergency Stop and the Autonomy
  section keep their existing markup and behaviour.

## Safety notes

- Layout changes (bento spans) live inside `@media (min-width: 901px)`
  only. At phone/tablet widths the grids fall back to the single-column /
  auto-fill rules in `responsive.css`, so there is no horizontal overflow
  at 320px (guarded by `tests/ui-styles.test.js` and the existing
  `tests/mobile-overflow.test.js`).
- The liquid-glass hero blobs are 420px/360px wide but sit inside `.hero`,
  which `main.css` gives `overflow: hidden` — they cannot widen the page.
- Liquid-glass motion stops under `prefers-reduced-motion`.
- Light theme has its own overrides in the same file (neumorphic shadows,
  clay shadows, glass tints, chrome fallbacks) — every style works in
  both themes.
- The existing `main.css` / `responsive.css` rules guarded by
  `tests/mobile-overflow.test.js` (KPI grid, `overflow-wrap`, table scroll)
  are untouched.
