## 2. Broken features

### 2a. Worker API vs live D1 — the main breakage (live-verified where stated)

- **B1 — `GET /api/articles` returns HTTP 500 live.** Fetched 2026-11-13 ~04:21 UTC: upstream HTTP 500 (3 attempts). Cause, verified against the real schema in an in-memory SQLite database: `backend/routes/articles.js:74-79` runs `SELECT * FROM articles WHERE status = ? … AND division = ? … ORDER BY publishedAt DESC`. The schema table (`database/schema.sql:103-124`) has **no `division` column** (it has `division_id` INTEGER FK) and **no `publishedAt` column** (it has `published_at`). SQLite error reproduced locally: `no such column: division`. The list endpoint can never succeed while D1 is bound. (When D1 is *not* bound it falls back to the in-memory list — which is why local tests pass.)
- **B2 — `GET /api/divisions` returns HTTP 500 live.** Fetched same time: upstream HTTP 500 (3 attempts). Cause: `backend/routes/divisions.js:46,57` query `SELECT * FROM divisions …`. **No `divisions` table exists** — the schema table is `business_divisions` (`database/schema.sql:68-83`). Same for the single-division path (`divisions.js:41`).
- **B3 — `GET /api/tools` D1 path would 500 (code-proven, live not fetched).** `backend/routes/tools.js:36,48` query `SELECT * FROM tools …`. No `tools` table exists — the schema table is `digital_tools` (`database/schema.sql:314-331`).
- **B4 — `PUT/PATCH /api/accounts` would 500 (code-proven).** `backend/routes/accounts.js:56` runs `UPDATE accounts SET status = ?, detail = ? …`. No `accounts` table exists (schema: `monetization_accounts`, `database/schema.sql:334-351`) and that table has **no `detail` column**. The `GET` D1 path (`accounts.js:37`) has the same wrong table but is masked by `.catch(() => ({results: []}))` falling through to the static fallback.
- **B5 — `GET /api/agents/status` is unreachable dead code.** In `backend/routes/agents.js:19-32`, the `parts.length === 3` branch calls `getAgent('status')` → null → 404 **before** the `parts[2] === 'status'` branch at lines 30-32 is ever reached.
- **B6 — `GET /api/analytics` D1 path queries a table that does not exist.** `backend/routes/analytics.js:26-28` selects `metric, value FROM analytics_snapshots ORDER BY recorded_at DESC`. Schema has `website_analytics` (`recorded_date, source, page_views, …`, `database/schema.sql:295-311`) — different table, different columns. Masked by `.catch`, so it silently returns the honest fallback forever; D1 analytics can never be read.
- **B7 — Agent activity is never persisted.** `backend/agents/business-manager.js:51-53` and `backend/agents/security-monitoring.js:26` insert into `activity_log`. No such table exists in the schema (the real table is `agent_activity_logs`, `database/schema.sql:234-250`). Both calls swallow the error and return `false` — pause/resume/disable history is silently dropped.
- **B8 — Publishing agent would fail if ever invoked.** `backend/agents/publishing.js:33` inserts `INTO articles (slug, title, division, excerpt, status, publishedAt)` — `division` and `publishedAt` do not exist in the schema (should be `division_id`, `published_at`).
- **B9 — `rate_limits` table does not exist anywhere.** `backend/middleware/rate-limit.js:25-40` probes it; the `catch` returns null and every Worker isolate falls back to its own in-memory map. Rate limiting therefore does not survive across isolates and is trivially bypassed by hitting different isolates. No migration or schema file creates this table.
- **B10 — `sessions` vs `user_sessions`: two session tables, only one in the schema.** Auth code (`backend/middleware/auth.js:28,60,75`) uses a table called `sessions` (`token_hash, owner_email, expires_at`). `database/schema.sql:38-53` defines only `user_sessions` (`session_token, owner_id, …`) — a different table with different columns. The `sessions` table exists **only** in `database/migrations/003_sessions.sql` (and `database/console-chunks/migration-003-sessions.sql`), which the owner ran manually on 2026-11-12. The documented fresh-deploy path (`README.md:102-122`, Option A *and* Option B) never applies 003 — a fresh deploy following the README breaks owner login (createSession’s INSERT throws → Worker catch → 500 “Internal server error”, `backend/worker.js:106-109`; there is no try/catch around it in `backend/routes/auth.js:52`).
- **B11 — Slug chaos: three different article-slug sets.** Only **12 of 25** slugs agree between the backend fallback (`backend/routes/articles.js:11-35`) and the sitemap/seed (`public/sitemap.xml`, `database/seed.sql`). The 13 that differ (backend → seed/sitemap): `ev-charging-at-home-beginners-guide` → `…-complete-beginners-guide`; `car-maintenance-checklist-monthly` → `…-12-things-every-month`; `motorcycle-buying-guide-first-bike` → `…-choose-first-bike`; `best-family-cars-compared` → `…-compared-space-safety-running-costs`; `what-is-ai-plain-english-guide` → `…-guide-beginners`; `7-free-ai-tools-that-save-time` → `…-that-actually-save-time`; `smartphone-buying-guide-2026` → `…-2026-what-matters-most`; `monthly-budgeting-50-30-20-rule` → `…-rule-explained`; `how-to-start-saving-small-income` → `…-with-small-income`; `travel-on-a-budget-plan-without-overspending` → `…-plan-trip-without-overspending`; `how-to-learn-new-digital-skill-30-days` → `…-in-30-days`; `home-workout-basics-no-equipment` → `…-no-equipment-needed`; `understanding-interest-loans-explained` → `…-explained-simply`. Consequence: a D1 single-article lookup by a backend-fallback slug 404s for 13 articles; by a sitemap slug it finds the seed row (see B13).

The SEO helper that generates the same wrong URLs (`backend/services/seo.js:58-76`, canonical `/articles/<slug>`) is dead code — never imported by the Worker or any route.
- **B13 — D1 article bodies are 49–65 words, not the full articles.** Measured in SQLite from `database/seed.sql`: every seed body is a ~55-word summary (e.g. id 1: 346 chars / 55 words; range 49–65 words across all 25), versus 641–959 words in `frontend/scripts/app.js`. But GA4 `G-JVSCJT2DHJ` is tagged on all 5 public pages (see §1.12) and Search Console is verified (verification file `frontend/google745797e85dfd966e.html` exists). ### 2b. Tool defects (executed, not just read)

- **B16 — Distance Planner outputs “1h 60m”.** `frontend/scripts/tools.js`, distance-planner calc: `m = Math.round((hours - h) * 60)` with no carry into hours. Executed: 599 km @ 300 km/h → `Travel time: 1h 60m` (should be 2h 0m). Any input whose fractional hour rounds to 60 minutes triggers it.
- **B17 — Maintenance Planner month-end overflow.** `next.setMonth(next.getMonth() + …)` overflows month-end dates: executed 2026-05-31 + 6 months → **01 Dec 2026** (should be 30 Nov 2026). Also rejects odometer 0 (`positive(v.lastKm…)`), so a brand-new car (0 km) cannot be entered.
- **B18 — Time Calculator “Subtract time” does nothing.** `frontend/scripts/tools.js`, time-calculator calc: the Subtract branch ignores both time inputs and returns only the duration with the note “Subtract this duration from a time of your choice.” A mode that performs no subtraction is decorative.
- **B19 — Chart labels invisible in light theme.** `frontend/scripts/charts.js:25-33` hard-codes label colour `#E9EFF7` (platinum) and bar-label colour `#E9EFF7`. On the light theme’s white card background that is **1.16:1** contrast (computed from the hex values) — effectively invisible. No theme-aware colour exists.

### 2c. Auth / security defects

- **B20 — No-D1 fallback accepts the raw `SESSION_SECRET` as a Bearer token.** `backend/middleware/auth.js:44-50`: `if (provided !== expected && token !== env.SESSION_SECRET)` — presenting the secret itself as `Authorization: Bearer <SESSION_SECRET>` passes `requireOwner`. - **B21 — Dashboard gate weakened for stored-but-unverified sessions.** `frontend/scripts/authentication.js:111-128, 196-200`: `render()` runs immediately on load and reveals `#dashboardContent` from the stored session **before** `validateSession()` (`GET /api/auth/me`) completes; and when `/me` fails with anything other than 401 (e.g. 500/503, or fetch throws) the session is kept with only an `unverified` flag in the status line while the content stays visible. The gate is “hidden until server session” only in the happy path.
- **B22 — No security headers from the Worker.** `backend/worker.js:29-56` sets only CORS headers. No `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, or `Strict-Transport-Security` anywhere in the backend. (Pages’ default headers were not inspected — live header check still open.)
- **B23 — Sitemap / robots live delivery not verifiable by text fetch.** Text fetches of `https://fs-ai-5w5.pages.dev/sitemap.xml` and `/robots.txt` on 2026-11-13 ~04:21 UTC both returned the **homepage HTML text**, not the XML / text file contents. That may be a fetcher artefact (no-JS crawl normalising to the SPA shell) or Pages serving the fallback for those paths — it cannot be distinguished from here. Needs a curl / live-browser check by the parent. Do not assume the files are served correctly live.

### 2d. Test-suite gaps (the suite passes but does not cover the breakage)

The dashboard is a static page behind a login, not a live Command Center.
4. **Agent pause/resume/disable works for only 8 of 16 agents and is not persisted.** `backend/agents/business-manager.js:109-131` maps only 8 registry ids to operational names (business-manager, content-creation, fact-checking, seo, publishing, analytics, monetization, security); the 6 research agents + digital-tools + others return `Unknown agent`. Any consumer switching from fallback to D1 loses fields.

13. **Unit Converter temperature path is latently broken.** `frontend/scripts/tools.js`, unit-converter calc: if `category` is Temperature while `from`/`to` still hold length units, it outputs nonsense such as `100.00 °km = 100.00 °m` (executed in Node). Unreachable through normal UI clicks (the category-change handler rebuilds the selects, `tools.js:330-344`), but the calc has no guard — a defensive fix, not user-facing today.
14. **Currency Converter defaults to rate 1.0.** `frontend/scripts/tools.js`, currency-converter def `rate: 1`: the default output reads `100.00 USD = 100.00 BDT` until the user types a real rate. The note text explains manual rates, but the default display is a 1:1 placeholder that could be misread as a real conversion.
